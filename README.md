# Video Export Optimizer

简体中文 | [English](README.en.md)

面向视频编辑与成片导出的Agent Skill：**先满足画质和内容要求，再减少导出过程中的等待、画面交接和重复读写。**

作者：毅直有办法。方法来自实际视频制作中的磁盘空间问题与导出流程实测。

## 它能做什么

安装后，支持隐式技能匹配的Agent可在你说“导出视频”“渲染成片”“生成MP4”等正常任务时选择此技能，不要求每次输入技能名。它会结合当前工程的实际能力，检查原素材、字幕、布局、图层和音轨，选择已经支持或能够验证的较快路径，并检查交付规格。

这是导出方法与只读验收工具的组合。实际渲染仍由项目中的Remotion、HyperFrames或其他引擎执行；项目需要相应能力或适配。安装此包不会自动把任意工程转换成WebCodecs，也不会接管剪辑软件的所有导出按钮。

## 平台与智能体范围

**通用流程面向macOS、Windows、Linux，也可供其他智能体接入。** Skill先检查实际执行端的系统版本、架构、浏览器／Electron、工程依赖、GPU与驱动，再选择可用路径；不要求使用Apple硬件或Codex。

| 环境 | Skill需要确认 | 当前验证范围 |
|---|---|---|
| macOS | 系统与芯片、运行时、工程及实际编码能力 | 现有M4 Mac个案实测；不代表所有Mac |
| Windows | Windows版本／edition／build、x64／ARM64、原生或WSL／Server、浏览器与GPU驱动、所需媒体组件 | 已加入适配规则；未完成本项目Windows视频导出验收 |
| Linux | 发行版／版本／内核、桌面或headless／容器、浏览器构建、驱动与GPU设备访问 | 已加入适配规则；未完成本项目Linux视频导出验收 |
| 其他智能体 | 是否支持Agent Skills或项目规则、实际可用工具与权限、技能加载和触发方式 | 通用入口不绑定Codex；未逐一实测其他宿主的自动匹配 |

没有一个“系统版本足够新”就保证所有硬编可用的门槛；同名浏览器也可能有不同编解码构建。Windows原生与WSL需分别检测。详见[跨平台与跨智能体适配](references/platform-agent-compatibility.md)。下方7.39倍等成绩仍限定实际测过的Mac环境，不能作为Windows／Linux的速度保证。

## Remotion与HyperFrames支持范围

| 工程 | 本Skill提供的指导 | 接入条件 |
|---|---|---|
| Remotion | 原素材直接供帧、保留组件合成、选择编码与封装路径、检查画质和资源占用 | 使用工程已验证的渲染入口；Web Renderer需满足其版本和效果支持范围 |
| HyperFrames | 减少PNG截图和逐帧往返，评估直接视频取帧与DOM叠层合成，检查音轨和成片 | 需要工程专用适配；任意HTML/CSS、多视频叠层和复杂混合效果不能自动转成等价Canvas |

**HyperFrames适用。** 该指导包含作者的本机适配实验，完整片数据单列在下方；当前包不附通用HyperFrames渲染器或一键硬编适配器。不支持的效果保留正确路径，不通过删除字幕、布局或图层换速度。

## 是否需要先安装WebCodecs

**使用WebCodecs导出路径，需要支持它的运行环境和已经接通的工程；安装Skill本身不要求先安装WebCodecs。** WebCodecs是浏览器内置接口，不是一个独立安装包。只装Node.js或一个名为WebCodecs的依赖，也不会让现有导出命令自动变成硬件编码。[接口说明](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API)

首次导出时，Agent应检查：

1. 实际导出所在的浏览器／Electron渲染进程提供所需接口，并在安全上下文中运行；本地开发可使用符合条件的localhost。不能只看浏览器名称或是否安装。[安全上下文](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts)
2. 本次编码格式、尺寸、帧率和码率等配置可用，使用`VideoEncoder.isConfigSupported()`检测；是否真正使用硬件另看运行时证据。[配置检测](https://developer.mozilla.org/en-US/docs/Web/API/VideoEncoder/isConfigSupported_static)
3. 工程能把原素材、字幕和图层合成为最终画面，并接到编码器、音轨处理和MP4封装。若采用Remotion Web Renderer，需要与工程版本配套的依赖，并检查其效果支持范围。[Remotion说明](https://www.remotion.dev/docs/web-renderer)

首次接入按“检查环境 → 补齐必要依赖与适配 → 验证代表片段 → 保留通过的项目配置”处理；以后普通导出复用。此包提供选路规则和成片检查脚本，当前没有通用的WebCodecs安装器或自动迁移所有工程的适配器。缺少WebCodecs时仍可沿现有渲染／FFmpeg路径优化等待、传输和封装，收益以本项目实测为准。

## 安装与正常使用

把本仓库的技能目录安装到当前Agent支持的技能位置。Codex可通过内置`$skill-installer`安装GitHub技能；也可以把本目录复制到用户技能目录，保持`SKILL.md`位于`video-export-optimizer/`根部。

其他支持Agent Skills的宿主按其当前官方说明加载同一目录；只支持项目规则的宿主，可在导出任务中读取`SKILL.md`及相关参考文件。`agents/openai.yaml`是可选的Codex专用元数据，通用流程和Python脚本不依赖该文件。不要把某个宿主的安装位置、策略字段或自动触发能力当作所有智能体的统一约定。

当前[官方技能文档](https://developers.openai.com/codex/skills/)列出的用户位置是`~/.agents/skills/`；部分现有Codex环境使用`~/.codex/skills/`。选择当前实例实际加载的位置，不在两处重复安装同名副本。

正常请求示例：

> 把这个项目导出为1080×1920、30fps的MP4，保留当前字幕、转场和音轨，按项目已经确认的画质设置输出。

本包的`agents/openai.yaml`为相应Codex宿主启用了`allow_implicit_invocation: true`；其他宿主使用各自的配置。隐式匹配由宿主Agent决定，不是“每次一定调用”的硬性拦截器。文件安装完成与真实会话中已经自动选中，是两个需要分别验证的状态。

### 接到固定项目的导出流程

若希望团队在同一个项目里无需记住技能名，可将下面的项目指令放入项目已使用的Agent指令文件，结合现有规则调整：

```markdown
当本项目的任务包含导出视频、渲染成片或生成MP4时，使用可用的
video-export-optimizer技能处理导出阶段，沿用本项目已确认的内容和画质设置。
先确认原素材、字幕图层、音轨、分辨率、帧率、编码及质量要求，
再选可用且经过验证的较快路径；不以降规格、删效果或复用失效音轨换速度。
实际执行既有项目导出入口，随后检查实际规格、码率、解码和必要的内容保留。
若技能不可用，按既有保真流程导出并说明，不能因此假装已经应用优化。
```

如果要求`npm run export`等命令自身每次都执行前后检查，需要将检查步骤真正接入该项目脚本。项目指令和技能不会改变一个普通命令本身的行为。本仓库不自动改动其他项目的导出脚本。

## 画质要求如何参与选路

- 沿用用户或项目已批准的分辨率、帧率、时间线、字幕图层和音频编辑。
- 按内容与交付目标确定码率；不把6.4Mbps套用到所有视频。
- 相同名义码率可能得到不同实际码率；同码率也不等于同画质。
- 浏览器端合成不支持的字体、CSS、转场、HDR或其他效果需要保真回退，不能静默丢弃。
- H.264与H.265都可能硬编；H.265不保证更快。是否使用硬编要看运行时证据。
- 硬件、项目和画面不同，收益不同；保留内存和磁盘余量。

更多实现决策见[路径说明](references/pipeline-routing.md)。

## 只读成片检查

附带脚本使用Python3.9+标准库，按三平台可移植方式编写；本轮实际运行检查在Mac，Windows／Linux仍待实机验证。先用环境助手收集基础系统信息；它不检查浏览器／GPU，也不证明硬编。

```bash
python3 scripts/inspect_environment.py --output environment-report.json
```

成片检查另需独立可用的`ffprobe`。完整解码另需`ffmpeg`；工具路径可显式提供，脚本不下载安装依赖、不修改视频。JSON按UTF-8写入，不覆盖旧报告。

```bash
python3 scripts/inspect_export.py --help
python3 scripts/inspect_export.py --input output.mp4 --output export-report.json
```

Windows装有Python launcher时可用`py -3`代替`python3`，否则使用实际Python路径；例如：

```powershell
py -3 scripts/inspect_environment.py --output environment-report.json
py -3 scripts/inspect_export.py --input "D:\Videos\成片.mp4" --ffprobe "C:\Tools\ffmpeg\bin\ffprobe.exe" --output export-report.json
```

把已确认的尺寸、帧率、时长或实际码率范围作为相应参数传入。报告能检查技术规格与解码，不能单独证明视觉清晰度、字幕图层保留、音画同步、硬件启用或所有设备兼容。

## 实测来源和边界

以下是作者在M4 Mac上的项目实测摘要。原素材全片为364.133秒、10,924帧、1080×1920、30fps，保留原素材、字幕、图层和时间线；已有三维短镜头作为素材使用，没有重算上游三维渲染。三组实验的计时口径和重复次数不同，分别阅读，不合并成跨框架排名。

**方法覆盖三平台，测量结果没有跨平台外推。** Windows／Linux的导出速度、实际硬编与画质应在对应系统／版本／驱动／工程上验证；其他智能体的加载与自动匹配也应另验。

### Remotion全片：两条完整路线，各3次

| 三次中位数 | PNG内存管道＋FFmpeg软件编码 | 直接供帧＋WebCodecs硬件编码 |
|---|---:|---:|
| 完整导出耗时 | 15:25.34（925.34秒） | 2:05.25（125.25秒） |
| 实际视频码率 | 6.333Mbps | 6.221Mbps |
| 最终MP4大小，十进制MB | 296.44 | 291.31 |
| 新增磁盘采样峰，MiB | 763.0 | 701.0 |
| 进程树RSS采样峰，GiB | 2.056 | 2.582 |

速度约为原来的**7.39倍**。每次计入原WAV新准备AAC、浏览器生命周期、画面输出、相同最终复制封装、fsync及基础检查；构建、预检和后验QA另计。固定交错顺序，各n=3，非随机实验；实际码率接近但不完全相等，OS页缓存未清空、无关应用未关闭。

这是供帧、合成／捕获和编码等整条路线的比较，不能归功于单一API。六份成片通过完整解码、帧数／时间戳、源取帧及音轨检查；抽样画面仍见颜色、字体边缘和阴影差异，未证明无损或画质提升。磁盘采样峰中位数少约8.1%，RSS中位数多约25.6%；不代表每次峰值都更低。

### HyperFrames全片：自定义适配前后，各1次

保留同源素材、字幕、布局和图层。原适配路径已经是**内存PNG＋WebCodecs硬编**；优化路径保留原runtime／GSAP／DOM叠层，减少PNG转换与逐帧跨进程往返，通过工程专用的视频供帧与捕获适配输出。两侧均观察到Apple VideoToolbox硬编，不是软件编码换成硬件编码的实验。

| 单次测量，n=1／版本 | 原适配路径 | 优化适配路径 |
|---|---:|---:|
| 全流程就绪耗时 | 34:55.67（2095.67秒） | 3:41.54（221.54秒） |
| 实际视频码率 | 约6.142Mbps | 约6.142Mbps |
| 最终MP4大小，MiB | 274.40 | 274.39 |
| 新增磁盘采样峰，MiB | 635.38 | 639.25 |
| 进程树RSS采样峰，GiB | 2.205 | 2.098 |

本次速度比约**9.46倍**，不是稳定倍速或上游HyperFrames默认性能。时钟从wrapper启动到音视频封装关闭、fsync及基础探测；共用音轨来自本轮原WAV一次准备，其**7.537秒准备成本在两次时钟外**，独立从原WAV导出时应另计。该口径与上方Remotion各次包含音轨准备的实验不同。

前后10,924帧／PTS及音轨检查通过，但画面不是逐像素一致；以原适配路径输出为参考的全帧YUV PSNR为**54.21dB**、SSIM为**0.998959**，747／10,924帧解码画面完全相同。该指标衡量前后差异，不是独立无损真值或跨框架绝对画质排名。此例磁盘采样峰略增，不能宣称所有资源都减少；不支持的复杂视频堆叠应回退，不将本次适配外推到任意HTML场景。

### H.264／H.265：同一30秒片段，各3次

| 三次中位数 | H.264 | H.265／HEVC |
|---|---:|---:|
| 完整导出耗时 | 10.085秒 | 10.057秒 |
| 实际视频码率 | 5.399Mbps | 4.782Mbps |
| 最终MP4大小，十进制MB | 20.955 | 18.641 |

900帧、1080×1920、30fps，同一组件合成与质量优先配置，两侧均观察到平台硬编，计入每次新音轨准备和相同最终封装。速度基本持平：只差约0.028秒，远小于单次波动。H.265文件小约11.04%，但实际码率也更低，未证明同画质能缩小这么多，不从30秒结果推算全片。

磁盘为文件分配空间采样，RSS为进程树采样，可漏瞬时峰或重复计共享页，不代表全部系统／GPU内存。以上均未完成连续完整人工观看、听取及用户验收，文件与自动检查不能替代这些步骤。

这些个案**不是安装后的性能保证**。细节、质量与资源取舍见[实测边界](references/benchmark-boundary.md)。仓库只含通用方法、原创辅助脚本和脱敏汇总，不包含原始视频、录音、私有工程、日志或第三方bundle。
